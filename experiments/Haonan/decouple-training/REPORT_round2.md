# Decoupled 训练:校准的多峰能否进入自由生成,一个轻量项能否收回其校准

> 对前面 issue 评论的后续回复,只补本轮新结果;模型/任务/损失等背景见原 issue。配套代码 + results 见本 PR 新增 `experiments/Haonan/decouple-training/` 下若干目录。

## 摘要

把答案位置上校准好的多峰分布放进**自由文本生成**、再用按意义合并的 Φ 归并成语义状态后,**多样性仍在**:decoupled 每个歧义档里,采样**覆盖到的幸存选项比例**都比 one-hot 高(j=2…5:0.85→0.56 对 0.66→0.38),one-hot 精确塌成单点。**但其校准衰减**:答案位置分布**到正确后验的距离**(total variation,0–1,越小越准)≈0.02,自由生成升到 0.31–0.52,且约 1/3 的样本**不落到任何单一选项**(含糊、或同时点多个)。一个轻量训练项能把这个衰减大致砍半,**但只在 Φ 读取一个可解析的承诺时**;完全自由散文里不起作用——好在代码 / 数学 / 推导的答案本就可解析。

## 设置(同原 issue,只列本轮新增)

模型(frozen Qwen3-4B + 小 LoRA)与四组训练目标(base / one-hot / decoupled / shuffle)同上,不重复。

- **为什么仍用小消元任务**:用它**量 calibration**——量校准要有已知的正确后验,消元任务(k 个选项消到 j 个幸存,真值 = 幸存上均匀)给得出;GSM8K 这类公认任务只有单一正确答案,没有可供校准的"正确分布"。公认任务(GSM8K)我们另测它**值不值得解码**(余量,见 §2)。
- **两种作答格式**(同一批题、同一真值,只改 Φ 的合并难度):结构化承诺(自由写一两句理由,末行写 `COMMIT: <选项>`,Φ 确定性解析该行)与完全自由文本(无承诺行,Φ = 独立模型 Llama-3.1-8B 判读每句承诺的选项)。
- **度量**:温度采样 N 条(默认 16,T=1.0)→ Φ 映成状态(结构化承诺解析那一行;自由文本由独立模型判读,即上面两种格式)→ 覆盖(覆盖到的幸存比例)/ 不同状态数 k_eff(落到几个不同选项,理想 ≈ j)/ 到真值的距离(校准);并排量答案位置分布到真值的距离作对照。item-level bootstrap CI。

## 结果

### 1. 自由生成的多样性,在按意义合并的 Φ 下胜 one-hot(对应评论一)

结构化承诺格式,decoupled vs one-hot,按幸存数 j(`state-emission/`):

| j (2/3/4/5) | 覆盖 | 不同状态数 k_eff | 到真值距离 | 答案位置到真值 |
|---|---|---|---|---|
| decoupled | 0.85/0.72/0.68/0.56 | 1.80/2.27/2.70/2.80 | 0.31/0.46/0.49/0.52 | ≈0.02(各 j) |
| one-hot | 0.66/0.54/0.41/0.38 | 1.32/1.63/1.70/1.90 | 0.41/0.53/0.67/0.68 | 0.50/0.67/0.75/0.80(=1−1/j) |

decoupled 每个 j 覆盖更多、状态更多、更接近真值;one-hot 答案位置精确塌成单点,采样随之塌。**所以"否则需要全新训练机制"对"多样性"这一点不成立。** 换成完全自由文本 + 独立模型判读(只够到 j=2):decoupled 覆盖 1.00、到真值 0.204,one-hot 0.82、0.350——排序在真合并下保住。

### 2. 五个度量上的 one-hot vs decoupled,以及 aliasing

- calibration / top-k 有效覆盖 / BAR-CMR / Markov-JS-KL:逐项见各目录 VERDICT/results。
- **样本数稳健性 + ECE(`sampling-robustness/`)**:decoupled 到真值距离随 N 在 **N≈16 收敛**(N=4:0.31 → N=16:0.14,覆盖饱和到 1.0);one-hot **各 N 皆塌**(距离 0.50、覆盖 0.20)——加样本数无法改善 one-hot。答案位置 ECE:确定题上两者都为 0,只在歧义题有区分(到均匀的距离 decoupled 0.025、one-hot 0.630)。
- **pass@1 的前提是可选择余量(`realtask-headroom/`)**:GSM8K base 模型 greedy 0.735、oracle-best-of-16 0.915(余量 +0.18),EvalPlus ≈0——说明这件事在哪类域才值得做。
- **Aliasing 没测干净(`markov-aliasing/`,负结果)**:理想度量需要"同一语义状态、不同文字历史"的成对输入。我用了任务里现成的一对——一种**直接告诉模型哪些选项还存活**,另一种**只给消去线索、让模型自己推断**——但这两条在"推断难度"上本就不同(decoupled 在直接告知时极尖、需推断时落后),它们下一步分布的差混进了推断难度,不能干净隔离别名。要测得换成纯改写对(同信息、异措辞)。

### 3. 校准衰减,与一个轻量收回项(`gen-calibration/`)

校准的定义见原 issue §3(证据不足时把概率铺平、充分时收紧);这里量为分布到正确后验的距离。我们直接量**自由生成**的校准(而非只在答案位置),因为两者在模型里走不同通路。衰减真实存在:decoupled 答案位置 ≈0.02,自由生成 0.31–0.52,约 1/3 不作承诺。

**收回项是一个新增的训练损失项**(不是推理技巧):把原 issue §3 那个"到已知真值的 KL"再加一份,落在生成里的承诺位置。取上下文 = `prompt + 一段固定推理 + "COMMIT:"`,读承诺位置上对各选项名词的 logits $s_{\text{commit}}$,加 $L_{\text{commit}} = D_{\mathrm{KL}}\!\left(p^{*} \,\|\, \mathrm{softmax}(s_{\text{commit}})\right)$,其中 $p^{*}$ 是同答案位置那项的已知真值(幸存上均匀)。总损失 = 原答案位置 $L_{\text{shape}}$ + $L_{\text{commit}}$ + 流畅度正则;teacher-forcing,训练中不采样。结构化承诺格式上的 A/B(decoupled → +该项):

| j (2/3/4/5) | 到真值距离 | 覆盖 | 不作承诺比例 |
|---|---|---|---|
| decoupled | 0.31/0.46/0.49/0.52 | 0.85/0.72/0.68/0.56 | 0.33/0.31/0.33/0.39 |
| + 收回项 | 0.20/0.23/0.25/0.32 | 0.99/0.96/0.95/0.80 | 0.04/0.08/0.11/0.14 |

差大致砍半、覆盖近满、不作承诺崩到个位数;答案位置校准仍 ≈0.01,通用文本困惑度 29.5 对 decoupled 30.0 对 base 32.3(未退)。**但只在 Φ 读取可解析承诺时成立**:换成完全自由文本,该项无改进(到真值 0.218 对 0.204)——它训练的是那个承诺位置,自由散文里没有这个位置可作用。

## 目前没想清楚 / 计划实验的部分

- 完全自由散文下的校准如何收回(可能需更重的序列级 / RL 项,或给任务一个结构化答案格式);
- 在 GSM8K 这类公认任务上做完整的 one-hot vs decoupled 对比——需先解决"开放任务上 decoupled 的训练目标怎么定"(无已知后验);
- aliasing 的干净测量(纯改写对);
- **不同任务下 Φ 如何构建**——用确定性解析器 / 执行器,还是需要一个子网络来做语义合并;
- 接入完整 trellis 后的 pass@1(归 decode / verifier 一侧)。
